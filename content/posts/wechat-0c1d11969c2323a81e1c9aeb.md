# Claude Code 上线「动态工作流」：它是干啥的、能干啥、怎么触发

前两天 Anthropic 发了 Claude Opus 4.8，同一天还顺手给 Claude Code 上了个「动态工作流」（[Dynamic Workflows](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code)），现在是研究预览阶段。模型升级体感平滑，反倒是这个动态工作流，值得花两分钟搞清楚。下面就讲三件事：它是干啥的、能干啥、怎么触发。

## 一、它是干啥的

以前让 Claude 干件大事，它一步步串着做；现在它会自己写一段脚本，把活拆开，一个会话里并行跑几十到几百个子 agent，最后只把汇总结果交回来。中间一堆过程都消化在脚本里，不来挤你的主对话。

跟以前手搓 subagent 比，省心的地方是：开几个、每个干啥、结果怎么收，都不用你操心，Claude 写进脚本自己安排。

## 二、能干啥

官方给的方向是跨代码库找 bug、大规模迁移这类活。我自己觉得最能对上的是三类：

- 广度优先的排查：比如"全库里还有哪些地方在调某个废弃接口"，一次派一批 agent 各扫一块，比单线程 grep 完再逐个读又快又全。
- 带验证的审查：代码审查最烦"看着像 bug 其实不是"，一个 agent 去找、几个独立 agent 去证伪，假阳性掉得很明显。
- 一个上下文塞不下的活：要改的面太大、文件太多，单会话注意力扛不住，拆成几十个小任务各自跑反而稳。

反过来，改一行配置、修一个明确的小 bug，别上这玩意儿，杀鸡用牛刀，还慢。

## 三、怎么触发

门槛先说：研究预览版，得先把 Claude Code 升到 v2.1.154 及以上。所有付费计划都能用，但 Pro 计划还要去 `/config` 里手动打开 Dynamic workflows，Enterprise 看管理员有没有启用。

触发其实就一句话的事：**提示词里带上关键词 `workflow`**，Claude 就会先写出一套编排计划，再按阶段把活拆给一群子 agent 去跑。比如开头直接说"请用 workflow 处理这个任务"，后面跟上目标、工作面、权限、停止条件就行。

另一种：开 `/effort ultracode` 让它自己判断当前任务要不要上 workflow（更激进、更烧 token）。它是 effort 拉满的那一档，等于「xhigh + workflows」，见下图。

![effort 档位：ultracode = xhigh + workflows](https://raw.githubusercontent.com/liuhedev/liuhedev.github.io/main/public/images/articles/0c1d11969c2323a81e1c9aeb/d117467c4be7b0c781d172e9c08a08989057f3a207379fe17bc774a4ab91aac8.jpg)

跑起来用 `/workflows` 命令看进度；生成的编排会存成一段 JS 脚本，落在项目的 `.claude/workflows/` 或主目录的 `~/.claude/workflows/`，能版本化、也能分享。具体边界（并发上限、权限、恢复）都写在[官方文档](https://code.claude.com/docs/en/workflows)里。

我搞了一个 skills 体检的工作流，提示词：”使用workflow 帮我做一个系统内所有skills的体检“。

通过 `/workflows` 可以看到正在跑的 agents：

![skills-health-check 工作流脚本](https://raw.githubusercontent.com/liuhedev/liuhedev.github.io/main/public/images/articles/0c1d11969c2323a81e1c9aeb/cba708e93b63bc97a8c283eb67287ea1275e95b1c16f2077ec90a283e5f20925.jpg)

**两个提醒**。

一是别当黑盒：它跑之前会把阶段计划列出来让你确认，别急着点过，先扫一眼它打算怎么拆、每步验什么。

二是别当免费：一轮跑下来几十上百个子 agent 都在烧 token（同时并发有上限，但累计数量很大），一个广度审查的消耗是单线程的好几倍，先拿个只读、范围小的任务试，看清花了多少再放大。
